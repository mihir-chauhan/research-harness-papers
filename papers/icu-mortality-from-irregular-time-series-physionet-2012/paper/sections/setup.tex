\textbf{Data.} PhysioNet 2012 set-a: \rhval{const/n_stays} ICU stays, each with up to \rhval{const/n_hours} hours of measurements of \rhval{const/n_vars} time-series variables and \rhval{const/n_static} static descriptors, and the in-hospital death label (\rhval{const/n_deaths} deaths; mortality \rhval{data/cohort-statistics/physionet2012_mortality/mortality/mean:pct1}\% in a cohort-statistics run). Only \rhval{data/cohort-statistics/physionet2012_mortality/obs_density/mean:pct1}\% of the hourly variable slots are observed, a stay has on average \rhval{data/cohort-statistics/physionet2012_mortality/obs_per_stay_mean/mean:0} observations, and height is missing for \rhval{data/cohort-statistics/physionet2012_mortality/height_missing/mean:pct1}\% of the stays. Mortality differs strongly by ICU type (ICU type 2, cardiac-surgery recovery: \rhval{data/cohort-statistics/physionet2012_mortality/icu2_mortality/mean:pct1}\%; type 3, medical: \rhval{data/cohort-statistics/physionet2012_mortality/icu3_mortality/mean:pct1}\%). As a sanity check on informative missingness, the AUROC of the total number of observations alone (no values) is \rhval{data/cohort-statistics/physionet2012_mortality/auroc_total_count_only/mean:3}. Negative values of $-1$ in the height/weight/gender descriptors are treated as missing; no other cleaning or outlier removal is done.

\textbf{Splits and seeds.} Each run is one (system, seed) pair and consists of \rhval{const/n_folds} stratified folds over patients (one stay per patient, so patient-level and stay-level splits coincide), giving \rhval{const/n_train_fold} training and \rhval{const/n_test_fold} test patients per fold; the seed fixes the fold assignment and the initialisation. All systems see the same folds for the same seed. Metrics are averaged over the test folds of a seed; the unit of replication for all comparisons is the seed (\rhval{const/n_seeds} seeds, so \rhval{const/n_runs_main} main runs). Normalisation statistics, imputation medians and all early-stopping decisions use training-fold data only (an inner \rhval{const/val_frac_pct}\% stratified split for early stopping).

\textbf{Tuning budget.} Every system is tuned on the same kind of data and with grids of similar size (Table~\ref{tab:tune}). Tuning uses two extra seeds (\rhval{const/tune_seeds} seeds, 100 and 101, distinct from the evaluation seeds): in each, \rhval{const/hold_frac_pct}\% of the training part of fold~0 is held out and models are scored by AUROC on it, so the test folds of that seed are never used. The tuning patients are nevertheless drawn from the same \rhval{const/n_stays} stays that the evaluation test folds later contain, which is an optimistic-selection risk discussed in Section~\ref{sec:limitations}. Stage 1 varies $C$ (LR), leaves and $L_2$ (GBDT), hidden size and learning rate (GRUs); stage 2 varies the learning rate and tree size (GBDT) or dropout and weight decay (GRUs) around the stage-1 winner. Fixed settings: GBDT learning rate \rhval{const/gb_lr:2} (unless tuned), at most \rhval{const/max_trees} trees, minimum \rhval{const/min_leaf} samples per leaf; GRUs use batch size \rhval{const/batch_size}, at most \rhval{const/max_epochs} epochs, patience \rhval{const/patience}, Adam, gradient-norm clip \rhval{const/grad_clip} and a \rhval{const/head_units}-unit ReLU layer in the head. The selected values are in Table~\ref{tab:tune}; the selection script (\texttt{experiments/select.py}) and all \texttt{tune} and \texttt{tune2} runs are logged.

\textbf{Hardware and runtime.} CPU only, \rhval{const/n_threads} threads, PyTorch for the GRUs and scikit-learn for LR and GBDT. A GRU run (five folds) takes on the order of one to two minutes and a summary-model run a few seconds; the run registry records durations. The platform's logged commands are exactly those in \texttt{method/driver.py} and \texttt{experiments/tune*.sh}. A first launch of the tuning driver failed for all cells because of a quoting bug and a missing output directory; those failed launches produced no metrics. The whole tuning stage was then executed twice (the first execution used an inconsistent task label and was superseded in the registry), and the log files of a few fast LR/GBDT cells collided when two cells started in the same second; the affected registry rows were removed and those cells re-run alone with identical results. All removed rows are kept in \texttt{results/runs\_failed\_launch.jsonl.bak}, and 65 accidental duplicate launches of ablation/sweep runs, which reproduced the first copies exactly, are in \texttt{results/runs\_duplicate\_launch.jsonl}.
