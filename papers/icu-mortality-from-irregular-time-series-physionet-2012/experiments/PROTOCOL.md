# Protocol
- Data: PhysioNet/CinC 2012 set-a, 4,000 stays, outcome In-hospital_death (Outcomes-a.txt). 36 time-series variables binned hourly over the first 48 h (last value in the hour wins), 5 static variables (age, gender, height, weight, ICU type; height/weight -1 -> missing). No imputation outside the training fold.
- Task `physionet2012_mortality`: predict in-hospital death from the 48 h record. Sweep `horizon` in {12, 24} truncates the record (main = 48).
- Splits: StratifiedKFold(5, shuffle, random_state=seed) on patients (one stay per patient). Each (system, seed) run trains 5 models, one per fold; metrics are averaged over the 5 test folds. Seeds 0-4 (different fold assignment and initialisation).
- Early stopping / GBDT stopping use a 15% stratified split of the training fold. Normalisation statistics come from the training fold only.
- Tuning: `--tune 1` runs hold out 25% of fold-0's training set (never the test fold of that seed) for tuning seeds 100 and 101 (different fold assignments from evaluation seeds 0-4, but the same 4,000 patients, so tuning data overlaps with later evaluation test folds; stated as a limitation). Grids: LR C in {0.003,0.01,0.03,0.1,0.3}; GBDT leaves {4,8,16} x l2 {1,10}; each GRU variant hidden {32,64,128} x lr {1e-3,3e-3}. Selection by mean hold-out AUROC. Other hyper-parameters fixed (see method/DESIGN.md).
- Hardware: CPU, 2 threads. Each run ~ 1-2 min.
- Evaluation identical for all systems: same folds, same metric code, same preprocessing.
- First launch of experiments/tune.sh failed for all 58 cells (JSON quoting bug in the driver, exit code 1 after ~4 s, no metrics); those rows are kept in results/runs_failed_launch.jsonl.bak and the driver was fixed (a second launch then failed because results/raw did not exist; those rows are in the same backup file) and re-run.
- The ablation and sweep drivers were accidentally started twice concurrently (one chain was then stopped by PID). 65 runs of `abl_decay`, `abl_counts` and `sweep_horizon` were therefore logged twice with the same seed and configuration; the second copies are moved to `results/runs_duplicate_launch.jsonl`, and in every one of the 65 pairs all metrics were identical to the first copy (a reproducibility check). The registry keeps one row per (group, system, seed). One failed `rh run` of the analysis script (an assertion triggered while the sweep was still running) is in `results/runs_failed_launch.jsonl.bak`.
- The tuning stage was executed twice: the first execution used the task label `tune_holdout` and was superseded (`rh supersede`); two rows of it and three rows of the second execution had log files overwritten by simultaneous runs (same name and second), were removed (kept in the .bak file) and the 3 affected cells re-run alone; metrics were identical to the removed rows.
