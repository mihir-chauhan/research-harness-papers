\paragraph{Tasks.} \emph{Trap MDP (maxbias).} State A is the start; action \emph{right} ends the episode with reward 0, action \emph{left} moves to state B with reward 0. State B has 10 actions, each ending the episode with reward drawn from $\mathcal N(-0.1,1)$; $\gamma=1$. Hence $V^\ast(A)=0$ (go right) while $q^\ast(A,\text{left})=-0.1$. Episodes: 300. \emph{Random MDP (random20).} 20 states and 4 actions; each state--action pair has 3 distinct random successor states with Dirichlet(1) probabilities and a fixed mean reward drawn from $\mathcal N(0,1)$; the observed reward adds $\mathcal N(0,\sigma^2)$ noise with $\sigma=1$; $\gamma=0.7$. An episode has 25 steps from a uniformly random start state; 1,000 episodes per run. State 0 is the designated start state for the bias metric. $Q^\ast$ is computed by value iteration for every run's MDP.

\paragraph{Runs and seeds.} Each \texttt{rh run} is one seed and contains 1,000 independent replicas (own tables, own noise, and, for random20, its own random MDP), vectorised in numpy. We use 5 seeds (0--4); statistics treat the seed mean over the 1,000 replicas as one observation, so all tests have $n=5$. Metrics: the \emph{final} value is the mean over the last 20 episodes, \emph{peak} is the maximum over episodes of the replica-mean start-state bias, and \emph{subopt\_all} is the suboptimal-action fraction averaged over all episodes (Section~\ref{sec:method}).

\paragraph{Hyper-parameters and tuning.} All systems share $\alpha=0.1$, $\epsilon=0.1$, zero initialisation, the same episode budget and the same seeds (the same seed index generates the same random MDPs for every system), taken from the Sutton--Barto setting rather than tuned; no system was tuned. $\alpha$, $\epsilon$, $\sigma$ and the number of actions are varied only as sensitivity sweeps and never used to select the headline configuration. Weighted Double uses $c=1$ and Maxmin uses $N=2$ estimators.

\paragraph{Configuration choice and pilot.} The random-MDP configuration ($\gamma=0.7$, 25-step episodes from random start states, 1,000 episodes) was fixed after a seed-0 pilot, run before any logged result, with $\gamma=0.9$ and 300 episodes, in which all estimators were still dominated by the transient from zero initialisation. The pilot also suggested that the start-state bias on random MDPs would be negative, so H3 was written knowing this. The pilot was not used to choose among methods.

\paragraph{Hypotheses and registered tests.} H1: on the trap MDP $Q$-learning overestimates $q^\ast(A,\text{left})$ and Double Q-learning has a lower final $Q$-bias (Welch test on \texttt{qbias\_final}, $n=5$). H2: on the trap MDP Double takes fewer suboptimal actions (\texttt{subopt\_all}). H3: on random20 $Q$-learning's final start-state bias is positive and Double removes it, and Double does not take fewer suboptimal actions (\texttt{bias\_final}, \texttt{subopt\_all}). H4: Q-learning's bias grows with $\sigma$ and with the number of actions, and Double stays below it (sweeps; read only at grid values). Significance level 0.05; tests are the Welch $p$-values of \texttt{rh compare}, with Double Q-learning as the reference (differences are Double minus the other system).

\paragraph{Ablations and sweeps.} Warm start at the true $Q^\ast$ (isolates steady-state from transient bias); simultaneous double update; $\sigma\in\{0.25,1,2,4\}$; $\epsilon\in\{0.1,0.3,1.0\}$ ($\epsilon=1$ is uniformly random, non-adaptive behaviour); $\alpha\in\{0.02,0.05,0.1,0.2\}$ on random20, and $n\in\{2,5,10,25,100\}$ actions at B on the trap MDP. The sweeps run Q-learning and Double Q-learning on random20, and all four systems on the trap MDP, 5 seeds each; the default point of every sweep is taken from the main runs (not repeated).

\paragraph{Compute.} The longest single run took 15 seconds on a shared CPU (2 threads), and the 250 experiment runs together sum to 24 minutes of run time. Code: \texttt{method/run.py} (committed before the main runs), \texttt{experiments/jobs.py} generates the run list, \texttt{analysis/make\_sweeps.py} aggregates the sweeps from the run registry.
