All experiments run on CPU (2 threads); each training run takes about ten seconds. Systems: the three baselines and the templated-language proxy, each with 5 seeds (0--4) on a single task (hidden-target rendezvous, two robots). Training uses 2000 Adam steps of 64 fresh episodes (learning rate $3\times10^{-3}$, $T=10$, $\Delta t=0.25$, hidden size 64, tanh). Validation targets use seed $10000+s$ and the reported test targets use seed $20000+s$ (held out). Hyperparameters were not tuned per system; the one setting used is the default in \texttt{method/run.py}. The sweeps vary the number of grid words per axis / tokens per slot $V\in\{2,3,4,6,8\}$ (language and discrete) and the continuous noise $\sigma\in\{0,0.1,0.3,0.6,1.0\}$, 5 seeds each; the $V{=}4$ and $\sigma{=}0.1$ settings are the main configuration. Statistical comparisons use Welch tests on 5 seeds, so they are low-powered and indicative only. Baselines are reimplemented simplified versions, not the authors' code. Because of an interruption, two sweep launchers overlapped and logged duplicate identical rows; duplicates were removed from the run registry by hand so each (system, setting, seed) appears once; the corresponding raw logs remain as orphan files in \texttt{results/logs}, and the stale pooled per-group sweep tables were deleted in favour of the per-setting summary. Added after review: a discrete-temperature sweep and a dense-evaluation re-run (Section~\ref{sec:ablations}); the main runs predate the code that prints per-evaluation progress and the \texttt{msgs\_used} metric, and re-running the main discrete configuration with the new code reproduces its metrics exactly.
