# Protocol
- Task = noise level (lorenz_n<pct>): 0, 0.5, 1, 2, 5, 10 percent of per-component clean-signal std. Lorenz-63 (10, 28, 8/3), 5 time-unit burn-in from (-8,7,27)+N(0,1), then 10 time units at dt=0.01 (1001 samples). Library: degree-2 monomials (10 per equation, 30 coefficients, 7 nonzero).
- Seeds 0-19 (test): each seed gives a new initial condition and noise realisation. Tuning seeds 1000-1004 (never evaluated). 20 seeds x 6 levels x 5 systems = 600 main runs.
- Systems: Weak-form STLSQ (method), FD-, SG-, Spline-, TV-STLSQ (reimplemented baselines). Same STLSQ, library, metrics, data for all.
- Metrics: support_exact (recovered support equals true support, all 3 equations), coef_err (||Xi_hat - Xi||_F/||Xi||_F), coef_err_oracle, false_pos, false_neg, runtime_s.
- Tuning: per system and noise level, grid over smoothing parameter x STLSQ threshold (tune.py, log in results/logs/tune.log), scored with ground truth on the tuning seeds. 5-35 configurations (FD 5 thresholds; SG 25; spline 35; TV 25; weak 25). Selection: highest exact-support rate, then lowest median coef_err, then the largest threshold. A tie means equal support rate and equal median coef_err on the 5 tuning trajectories; it does not require identical models. Tie diagnostic (method/tie_check.py, registered runs in group tune_diag, tuning seeds only): of the 19 cells with a tie, 17 have tied configurations that return identical models on all 5 trajectories; for FD at 5 % (thresholds 0.05, 0.1; models differ on 3 of 5 trajectories) and spline at 10 % (0.4, 0.6; 1 of 5) they differ. In both the selected threshold has the lower mean tuning error, and a mean-error tie-break would select the same configuration in all 30 cells, so the rule was not changed again and no run was repeated.
- Revision after the audit: the first tuner version resolved ties by grid order (smallest threshold). That decided the threshold in 19 of 30 system x level cells (every cell at 0, 0.5, 1 %; weak at 2 %; FD at 5 and 10 %; spline at 10 %). The rule was replaced by the deterministic one above (same tuning seeds, same grids, same for all systems; smoothing parameters unchanged), all main runs, the width sweep and the exponent ablation were re-run, and the first-version rows are kept in results/runs.jsonl as superseded (`rh runs --all`); first-version values: method/tuned_v1.json, results/logs/tune_v1.log. The new rule was chosen after the first results had been seen; the threshold-grid runs below show both choices for every cell.
- Hardware: Apple M1 Pro CPU, 2 threads, a run takes 0.1-3 s of compute (plus about 1 s of interpreter start-up). Wall-clock: about 30 min for the first version and about 20 min for the revision (interrupted once and resumed; experiments/launch.py skips jobs already in the registry) (two processes at a time), plus about 5 min per tuning pass. The tie diagnostic (method/tie_check.py, kind sanity, group tune_diag, tuning seeds 1000-1004) repeats the tuning grid: six registered runs, one per noise level, about 35 s each. A first execution did all six levels in one 3.6-min run under the task name `tuning_seeds`, which is not a task of the study; it is superseded in the registry (`rh runs --all`) and gave the same values.
- Ablations/sweeps (override of tuned values): sweep_width (weak width, n2 and n5), abl_p (test-function exponent, n2), abl_libstate (library on smoothed state for SG/Spline, n2 and n5).
- Threshold grid (group sweep_thr, diagnostic, test seeds): one run per system x level x seed (`run.py --thr-grid 0.05,0.1,0.2,0.4,0.6`) builds the regression problem with the tuned smoothing parameter once and reports support_exact, coef_err, false_pos, false_neg for each threshold (metric keys suffixed `_t<thr>`). 5 systems x 6 levels x 20 seeds = 600 runs. analysis/make_report.py asserts that the grid value at the tuned threshold equals the main run and that the value at the first-version threshold equals the superseded main run.
- Launcher: experiments/launch.py; tables, tests and figures: analysis/build.sh.
